# 边下边播实现与验证

2026-10-25。当前源码增加渐进式播放，电视端 API/HLS 协议保持兼容。这是服务端源码更新，既有 Release 安装包不自动包含本功能。

## 行为

此前必须下载完独立音视频、完整处理并合并后，才启动 HLS。现在按 MP4 box 增量读取：初始化段和完整 moof/mdat 交给原样官网公开 worker；音视频各至少一个媒体片段输出后，FFmpeg 即可从仅监听 `127.0.0.1` 的随机路径输入持续读取，生成 2 秒 HLS 分片。电视仍在首个 HLS 分片就绪后开始播放。

输入读到当前文件尾部会等待新增数据，只有对应处理任务成功结束且现有字节全部读完才发送 EOF。网络中断、格式错误、超时或主动取消会关闭输入、终止处理，删除未完成缓存，不将半集缓存当作完整媒体。上游地址仍受原有域名白名单约束；签名 URL 和播放参数不写入日志或报告。

下载完成后生成原有合并 MP4 缓存，随后同集跳转使用本地文件快速定位。正在下载的源按顺序处理，跳转通过解码并丢弃目标时间之前的数据完成；远距离前跳仍可能等待下载。未实现 Range 分片并发预取、自适应码率或离线下载。总缓存计入保留的独立明文轨道，最多三集、约 1 GiB、TTL 15 分钟，停止服务清理。

## 受控验证

`server/tests/progressive.test.mjs` 包含：

- MP4 任意网络拆包、扩展长度头、截断和超大/无长度 box 拒绝。
- 临时文件 EOF 时持续等待、追加后可读、完成后才结束、重播和撤销源地址。
- 真实 FFmpeg 生成 16 秒独立 H264/AAC fMP4，测试 SDK 只转发这些自生成明文字节；两路下载在第八个 mdat 后阻塞。**未释放后半段前，产品 PlaybackManager 已 ready，首个 HLS 分片严格解码成功，且清单无 ENDLIST。**
- 同集跳到第 2 秒仍可在下载未完成时 ready；释放下载后 HLS 时长约 14 秒、包含 ENDLIST，完整解码成功，后续命中合并 MP4 缓存。
- 开播后下载失败、主动停止两种情况均不保存半集缓存，进程、源地址和目录完成清理。

完整服务端回归 57 项全部通过，0 跳过。随后针对 EOF 与完成标记竞争的修正，再次运行 6 项渐进式测试全部通过。命令和记录摘要见 [validation.json](validation.json)。这证明产品管线能在下载完成前产出可播放 HLS；官网媒体验证另见下节，真实电视仍未验收。

## 官网实测

使用 `server/scripts/probe-progressive.mjs`、匿名官网、锁定且 SHA 校验的公开播放器组件进行实测。前两次完整链路在媒体下载前分别遇到 `SOURCE_INVALID_DATA` 与 `SOURCE_TIMEOUT`，tracks 为空，不能记为真实媒体解码成功。保留[首次失败](live-attempt-1.json)和[第二次失败](live-attempt-2.json)。

随后用当天取得并通过产品解析器验证的公开详情 HTML（46 集目录）固定元数据输入，**播放信息、CDN 媒体和官网 worker 均为本轮真实调用**。这一轮[实测成功](live-retained-detail.json)：

| 指标 | 结果 |
| --- | --- |
| 首个 HLS ready | 7,983 ms（含初始化和受控下载等待） |
| 首播时两路 CDN 状态 | 两路均未结束；一路已被测试闸门阻塞 |
| 完整下载与缓存合并 | 16,330 ms |
| 输出 | 55 个 HLS 分片，ENDLIST 存在 |
| 官网时长 / HLS 时长 | 108.331 / 108.333333 秒 |
| 完整严格解码 | exit 0，108.366667 秒 |

这证明真实媒体通过当前分片处理管线实现了提前开播；详情页依赖用了留存的公开 HTML，因此不能称为所有步骤均实时成功，也不能保证其他内容、网络或设备相同。报告不包含签名 URL、访问参数或媒体字节。

最后重新从**实时官网详情页**发起完整链路，[整链实测成功](live-complete-chain.json)，无需留存详情输入：首个 HLS **7,779 ms**，两路下载均未结束；完整下载及缓存合并 **15,012 ms**；55 个分片、ENDLIST、整集解码 exit 0，解码时长 108.366667 秒。这是同一公开样本的成功结果，仍保留前两次上游失败，不能推断全片库始终可用。

## 运行与复现

停止服务后更新本分支的完整 `server/` 目录，再按原方式运行 `windows/start.cmd`。保留现有数据目录、播放器哈希校验与运行库配置；无需替换电视 APK。若只使用旧 Release 压缩包，播放仍是整集准备方式。

```sh
cd server
npm test
# 需要 Node 24、可用 FFmpeg，以及可访问官网；输出文件必须不存在。
node --use-env-proxy scripts/probe-progressive.mjs /absolute/new-report.json
```

实测脚本在每路八个 mdat 后暂扣后续下载，待首个 HLS 就绪再放行，并核对完整 HLS 解码与时长。报告只保留内容 ID、时序、字节数和结果，不写媒体 URL、访问参数或媒体文件。因刻意阻塞下载，报告耗时不能直接当作自然网络下的首播性能。`HONGGUO_FFMPEG` 可指定 FFmpeg 路径。若要单独验证媒体链，可用 `HONGGUO_PROBE_DETAIL_HTML=/path/to/public-detail.html` 指定自行保存的公开详情 HTML；报告会明确标注元数据来源和 SHA-256，不影响生产服务。

本轮没有 Windows Server / E3 核显 / Chromecast 真机；不承诺实机启动时间或无缓冲。网络持续速度或转码速度不足仍会缓冲，官网不可用/格式变化也仍可能导致失败。

# 客户端扫码与账号列表预览版（0.1.2）

本版通过**红果官网正式扫码登录**建立服务端会话。二维码由官网页面/SDK 生成，手机上用红果 App 扫码并确认；服务端随后调用官网账号信息接口验证，成功才保存会话。无需 ADB、root、手机注入，也无需在本项目输入手机号或验证码。

通过官网扫码取得的会话已实测可读取官方 App 的手机观看历史和云收藏。首页置顶最近观看的 10 部系列，按观看时间倒序；“云历史”和“云收藏”菜单显示完整读取结果，并提供刷新。原有数据单独保留在“本机历史”和“本机收藏”。一个服务端共享一个账号。

**云收藏当前只读。** 添加收藏的受控测试被官网以 `101144` 拒绝，原收藏重读后保持不变。客户端明确提示在手机管理，配对 API 的 PUT/DELETE 返回 `ACCOUNT_FAVORITES_READ_ONLY`（501）；不会展示写入成功。原生短信登录、其他 App 接口和完整写入上下文尚未复原。

## 在现有 Windows 安装上更新

1. 先运行原安装目录的 `windows\stop.cmd`。
2. 将账号预览更新 ZIP 解压到**原安装目录**，合并 `server`、`windows` 和 `docs` 文件夹，允许覆盖同名源码。服务端更新 ZIP 不含 `data`、`runtime`、`local.settings.json` 或账号凭据。另行安装配套 0.1.2 APK 才有电视扫码及云列表菜单，不需要重跑服务端 setup。
3. 在服务器安装 Microsoft Edge 或 Chrome（已有则复用），运行 `windows\start.cmd`。
4. 双击新增的 `windows\account-login.cmd`，或在服务器本机浏览器打开启动窗口给出的 `http://127.0.0.1:8751/account`。自选端口按启动窗口为准。
5. 点击“生成登录二维码”。使用带“扫一扫”功能的红果 App 扫码，并在手机确认；旧版可能没有该入口。页面显示“官网账号已登录”才算完成验证。

账号页面只接受服务器本机连接和本机 Host，不通过局域网 IP 或端口映射提供管理。若使用远程桌面，在远程桌面里的服务器浏览器打开页面；二维码可用手机扫描电脑屏幕。浏览器与临时配置只在登录/验证期间存在，通过进程管道控制，不开放调试端口。

## 在电视客户端登录

当前分发的是包名 `cn.hongguotv.preview` 的“红果 TV 账号预览”，与旧版并存；由于签名不同，不覆盖仓库的 0.1.0 APK，也不要求卸载旧版。两者的本机数据独立，预览版需要重新配对。

更新配套 APK 和服务端后，电视完成配对即可打开顶部“账号”菜单，生成二维码、查看扫码状态、验证保存的会话或退出账号。手机扫码确认后，服务端仍须向官网验证成功才启用会话；客户端不会收到 Cookie 或登录密钥。

二维码按登录操作 ID 查询，每 1.5 秒更新状态，仅发起操作的配对设备可读取或取消该操作。离开账号页或将应用切到后台会取消尚未完成的扫码；若手机确认恰好完成，迟到的取消不会清除已经验证的会话。重新生成会替换旧操作，本机管理页面仍可使用。

电视的“退出账号”清除服务端保存的会话，然后可重新扫码切换账号。本机收藏和本机观看历史不随官网账号切换。账号列表缓存只存内存，60 秒到期，账号 revision 变化或退出后不复用旧缓存。列表请求失败显示错误，不伪装为空列表；手机修改收藏后可用菜单“刷新账号列表”立即核对。

## 保存、重新验证与退出

- 验证成功后，仅保存适用于 `hongguoduanju.com` 的 Cookie 与显示名，凭据不返回电视或账号状态 API。完整 Cookie 仅用于 `https://hongguoduanju.com`。经持号者授权并实测同账号后，仅 `sessionid` 可用于 `https://reading.snssdk.com` 上固定的历史/收藏路径（aid=8662）；不发送到任意 App 路由、媒体 CDN、短链或其他域，重定向仍被拒绝。
- 服务重启显示“已保存账号，请验证会话后使用”；点击“验证已保存的会话”，向官网确认有效后启用。不会仅凭磁盘上有 Cookie 就显示已登录。
- “取消扫码”会停止当前浏览器；二维码/登录操作最长五分钟，官网也可能更早判定二维码过期。过期后重新生成。
- “退出并清除本机会话”关闭本项目登录浏览器并删除本地会话文件及密钥。它是本机清理，不声称撤销服务端所有会话，也不会让手机退出账号。

账号数据位于选定数据目录的 `account/session.enc` 与 `account/session.key`，使用 AES-256-GCM，密钥留在同一本机目录。它避免明文凭据落盘，不能防御已能读取密钥的本机用户。Linux 创建目录/文件权限为 0700/0600；Windows 依赖所选目录的用户 ACL。不要分享整个数据目录或密钥文件。

## 环境与故障

Node.js 仍为 24+，不增加 npm 运行依赖。默认查找常用 Edge/Chrome 安装路径；找不到时，启动前设置完整程序路径，例如 PowerShell：

```powershell
$env:HONGGUO_BROWSER = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
.\windows\start.cmd
```

浏览器继承现有 HTTPS/HTTP 代理并保持 TLS 校验。当前登录助手不支持代理 URL 内带用户名/密码。Linux 容器测试可显式设置 `HONGGUO_BROWSER_NO_SANDBOX=1`；普通 Windows 安装不需要该设置。

- 显示缺少浏览器：安装 Edge/Chrome 或设置上述路径，重新生成二维码。
- 官网不可用、组件变化或验证失败：页面给出错误，保留“未验证”状态；重试或更新服务端，不能用二维码确认事件代替官网会话验证。
- 会话过期：重新扫码。错误信息和服务器日志不包含 Cookie、手机号或二维码 token。
- 主程序停止会关闭本项目控制的浏览器；不会操作你的日常浏览器配置或手机进程。

官网 SDK 当前使用动态 chunk `5y` / `32` / `u2` 与模块 `V1` 验证会话；这是本次真实官网验证的适配边界，官网部署调整后可能需要更新。没有在本项目重写 `a_bogus`、伪造设备注册或跳过手机确认。
